# FireVibe

### 把闲置的 Fire TV 遥控器，变成 Mac 的遥控器和麦克风

躺在抽屉里的那支遥控器，可以拿来切歌、调音量、翻 PPT、一键唤起常用应用，
按住麦克风键说话文字直接落进输入框，还能对着电视和空调发红外。

**[⬇︎ 下载最新版](https://github.com/tankxu/firevibe/releases/latest)** · macOS 12+ · Apple Silicon

## 为什么会有这个东西

Fire TV 遥控器是一支做工不错的蓝牙遥控器 —— 21 个键、带麦克风、带红外发射管、
一节电池用几个月。买了 Fire TV Stick 的人家里通常都有一支，而它除了配那台 Stick
什么也干不了。

FireVibe 把它接到 Mac 上，让这 21 个键**每一个都能干你想让它干的事**。

一些真实用法：

- 靠在沙发上看视频，用它切集数、调音量、暂停
- 讲 PPT 时握在手里翻页，不用回到电脑前
- 做饭时按住麦克风键说一句，Mac 上的 AI 助手就收到了
- 睡前按一下，关掉电视、关掉空调、Mac 进入睡眠 —— 一个键三件事

## 21 个键，随你定义

每个键有**短按**和**长按**两个位置，各配一个动作。一共 12 种动作可选：

| 动作 | 干什么 | 举例 |
|---|---|---|
| **映射按键** | 合成一次键盘按键，可带 ⌘ ⇧ ⌥ ⌃ | 方向键翻页、`⌘←` 后退 |
| **输入文字** | 把一段预设文字打进当前光标处 | 常用邮箱、地址、代码片段 |
| **打开应用** | 按 bundle id、应用名或路径打开 | 一键唤起 Claude、微信 |
| **AppleScript** | 跑一段脚本，几乎能驱动所有 mac 应用 | 让 Music 下一曲、给备忘录加一条 |
| **执行命令** | 交给 `/bin/sh` 执行 | 跑一个自己写的脚本 |
| **HTTP 请求** | 发一个 GET / POST，可配重试和超时 | 触发 Home Assistant、webhook |
| **红外遥控** | 让遥控器打一发红外码 | 开关电视、调空调（[详见下文](#遥控电视和空调)） |
| **语音转文字** | 系统离线识别，说完出字 | 说一句话直接进输入框 |
| **第三方语音输入** | 麦克风键在硬件层变成一个修饰键 | 触发你惯用的语音输入工具 |
| **按住说话** | 按住时把麦克风送进虚拟声卡 | 开会、连麦 |
| **开始 / 停止说话** | 点一下开，再点一下关 | 长时间录制不用一直按着 |
| **录音** | 按住录、松手存到「下载」 | 随手记一段语音备忘 |

### 没配过的键，装完就能用

方向键 / OK / 返回当键盘用；音量 / 静音 / 播放暂停走系统媒体键 —— 调音量时有
macOS 原生的音量提示。快进快退映射成「下一曲 / 上一曲」而不是快进几秒，
因为后者在 macOS 上几乎没有应用支持。

不想要某个键？可以单独禁用，它就彻底不响应。

### 多套方案，随时切换

写代码一套、看视频一套、讲 PPT 一套，在主界面下拉切换。方案可以改名、复制、删除。

### 软遥控器同步高亮

界面左边那支遥控器会**实时高亮你在实体遥控器上按下的键** —— 配置时不用猜
「这个键叫什么」。反过来，点软遥控器上的按键也会直接执行它配好的动作，
可以坐在电脑前先试效果。

### 长按多久算长按

默认 350 毫秒，设置里能调。配了长按的键，按住到时间立刻触发长按动作，
并且不再触发短按。

## 说话就出字

麦克风键是这支遥控器最好用的地方。三种方式，按习惯选：

### 内置语音转文字（建议先试这个）

**不用装任何东西。** 给麦克风键配上「语音转文字」，按住说话、松手，
识别出的文字直接进当前输入框。识别在本机离线完成，**不联网**。

设置里可以选识别语言，还有一个「识别后自动回车」—— 在 AI 助手里就是说完直接发送。

说话时屏幕底部会浮出一条电平条，让你知道确实在收音。

### 交给你惯用的语音输入工具

已经有习惯的第三方语音输入工具？给麦克风键配「第三方语音输入」，选一个修饰键
（和那个工具里设的热键一致即可）。

按下麦克风键时，这个键会在**硬件层**直接变成所选的修饰键 —— 系统收到的事件和你
真的按下键盘完全一样。这一点是关键：**有些工具只认硬件来源的按键**，软件合成的收不到。

> 这个映射只作用于**这台遥控器**，不碰你的键盘；退出应用时自动还原。

### 当一支普通麦克风用

在界面上点「安装」，装上随应用附带的虚拟声卡 **FireVibe Mic**（需要管理员密码）。
之后任何应用 —— 会议软件、录音工具、语音输入 —— 都能在麦克风列表里选到它。
按下遥控器的麦克风键，声音就送进去了。

还有个贴心的：**说话时自动切输入设备**。按下说话键把系统默认输入切到虚拟声卡，
说完切回你原来的设备，实测 3~13 毫秒，你察觉不到。

<details>
<summary>为什么要自带一块声卡，不直接用 BlackHole？</summary>

语音输入工具通常会把传输类型标记为「虚拟」的声卡从麦克风列表里滤掉，
BlackHole 就是这么被漏掉的 —— 它压根不出现在候选列表里。

`FireVibe Mic` 基于 BlackHole 只改了一处：让它声明自己是 USB 设备。
整个改动就一行，记在 [`driver/build.sh`](driver/build.sh) 里。

</details>

## 遥控电视和空调

这支遥控器**自带红外发射管**。给某个键配上「红外遥控」，按它就发一条红外码 ——
电视、机顶盒、投影、音响、空调都行。

### 码从哪来

**先搜内置码库。** 编辑动作时直接搜品牌或型号（`sony bravia`、`daikin arc480`…），
挑一个按键就填进去了。内置 **1605 个设备、25767 条码**，来自
[Flipper-IRDB](https://github.com/Lucaslhm/Flipper-IRDB)（公有领域），常见家电基本都有。

**库里没有就自己抓。** 需要一个外部红外接收器 —— 遥控器和 Mac 都只能发不能收。

最省事的是 **ESP32 + 解调型 38 kHz 接收头**（TSOP38238 / VS1838B，十几块钱），
刷 [IRremoteESP8266](https://github.com/crankyoldgit/IRremoteESP8266) 的 `IRrecvDumpV3`
示例，对着原装遥控器按一下，串口就吐出：

```
uint16_t rawData[67] = {9000, 4500, 560, 1690, 560, 560, ...};
```

**整行复制，粘进「红外码」输入框就行** —— 带不带 `uint16_t rawData[67] =` 和分号都认。
网上码库最常见的 Pronto hex（`0000 006D ...`）也能直接粘，自动识别格式。

有 Flipper Zero 的话更顺手，它自带学习和存档。

> ⚠️ **抓空调码要调大缓冲**：`kCaptureBufferSize` 提到 1024 以上、`kTimeout` 提到 50。
> 默认值会把三百多个脉冲的空调帧**截断** —— 抓出来像条短码，发出去没反应。
>
> ⚠️ 抓出来显示 `UNKNOWN` 不代表失败。FireVibe 要的是原始时序，认不认得出协议无所谓。

### 两种遥控器的红外不一样

和麦克风一样，这里也分两派，应用会按认出来的型号自动切换：

| | 热麦克风那派 | 按住才出声那派 |
|---|---|---|
| 谁发射 | 按键时应用现场发一条 | **遥控器自己发**（码事先烧进去） |
| 电脑关着 | 不发 | **照发** |
| 能绑哪些键 | 都行 | 只有 **开关机 / 音量± / 静音** 四个，且只能配短按 |
| 单条码长度 | 空调整帧没问题 | ⚠️ **仍在完善**：目前只支持约 **70 个脉冲**以内的短码 |
| 生效时机 | 立刻 | 保存后写进遥控器，十几秒，要遥控器醒着 |

后一种是把码写进遥控器自己的按键表（Fire TV 的「设备控制」走的是同一条路），
所以按键即发、不经过电脑 —— 电脑睡着了也照样能关电视。

> ⚠️ **「按住才出声」那派的红外还在完善中。** 一帧的电视 / 机顶盒码
> （NEC、Samsung 多是 67~68 个脉冲）已经跑通并实测过；再长的码遥控器会丢掉、
> 改发一条毫不相干的码，所以应用会在保存时直接拦住。真实上限还没摸清 ——
> 同一条码在不同形状的按键表里表现不一致，机制未明。
> **长码（空调、部分风扇）请用前一种遥控器**，它走 blast 通路，
> 319 个脉冲的空调整帧实测通过（CRC 正确、逐字节一致）。

把动作删掉再保存，就能把烧进去的码清掉。没配过红外时应用不会去动遥控器，
电视「设备控制」写进去的音量、静音红外不受影响。

## 还有这些

**常驻状态栏。** 右上角有个遥控器图标，点开可以显示窗口或退出。
关掉窗口只是隐藏，遥控器照常工作。

**看得到电量。** 主界面显示遥控器电量，每 5 分钟读一次。

**使用统计。** 总触发次数、今天按了多少、活跃天数、按键排行、动作类型分布、
语音用了多少次 —— 能看出哪个键配得值、哪个键白配了。

**配置可以带走。** 设置里能导入导出配置文件，也能直接在访达里打开它。
换电脑、备份、和别人分享一套配置都方便。

**换遥控器不用重来。** 界面上有「配对新遥控器」，扫一遍蓝牙设备、选中、
逐个按键认一遍就好。它会自己认出麦克风是哪一派。

**中英文。** 设置里切换，即时生效。

**自动检查更新。** 有新版本时界面上会提示。

## 支持哪些遥控器

| 型号 | 状态 |
|---|---|
| **Fire TV Alexa Voice Remote（3rd Gen）** | ✅ 已实测，21 个键全部完成测绘 |
| **另一款同样自称 Fire TV Remote 的**（PID `0x0425`，市面常见） | ✅ 已实测。按键完全一致；麦克风是「按住才出声」型 |
| 其它 Fire TV 遥控器 | ⚠️ 未实测，但大概率能用 —— 在应用里「配对新遥控器」走一遍 |

### 两种麦克风，行为是反的

| | 热麦克风 | 按住才出声 |
|---|---|---|
| 怎么开 | 电脑发一条命令，之后一直出声 | 遥控器自己推，**只在按住麦克风键时** |
| 物理按键 | 无所谓，按不按都出声 | 必须按住，松手立停 |

**应用会自己认出来** —— 连上后静悄悄试一次，出声就是热麦克风，不出就是按住型，
结果记下来，换遥控器时重新判。

认成「按住才出声」时，语音动作要配在**长按**里 —— 短按点一下就松手，
遥控器那边一帧音频都不会出。这时动作编辑器的「短按」栏不再提供语音动作，
主界面也会给一个「移到长按」的一键修复。

> 亚马逊自家的 BLE 遥控器不止一款，固件里能查到 16 个型号标识，
> 但**标识不代表机器**（仿品会直接借用）。所以 FireVibe 的按键靠配对时实地测绘、
> 麦克风靠连上后实测判定，都不靠型号猜。细节在[开发笔记](docs/DEVELOPMENT.md)里。

## 开始使用

### 第一步：把遥控器配对到 Mac

> **先把 Fire TV Stick 断电。** 遥控器一次只能配一台设备，Stick 通着电会把它抢回去。
>
> **必须用 1.5V 碱性 AAA 电池。** 1.2V 充电电池撑不住蓝牙射频的峰值电流，
> 表现是时连时断，很容易被误判成软件问题。

1. **解除它和 Fire TV 的配对**：同时按住 **← 方向左 + ↺ 返回 + ☰ 菜单**，保持 **12 秒**

2. **进入配对模式**：按住 **⌂ 主页** 键 **10 秒**。指示灯先慢闪琥珀色，
   准备好接受连接时变成**快闪**

3. Mac 上打开 **系统设置 › 蓝牙**，找到遥控器点「连接」。连上后指示灯闪蓝色

此时按键还不会有反应，继续下一步。

### 第二步：下载安装

1. 到 [**Releases**](https://github.com/tankxu/firevibe/releases/latest) 下载
   `FireVibe-x.y.z-macos-arm64.zip`

2. 解压后把 **FireVibe.app** 拖进「应用程序」

3. ⚠️ **首次打开会被 macOS 拦下来**（安装包未经 Apple 公证）。
   **右键点图标 →「打开」**，在弹出的对话框里再确认一次

   <details>
   <summary>命令行等价写法</summary>

   ```bash
   xattr -dr com.apple.quarantine "/Applications/FireVibe.app"
   ```

   </details>

### 第三步：给权限

打开 **系统设置 › 隐私与安全性**，把 FireVibe 加进这两项：

| 权限 | 用途 |
|---|---|
| **输入监控** | 读取遥控器按键。不给就完全收不到按键 |
| **辅助功能** | 代为按下键盘按键、输入文字 |

> 勾完「输入监控」要**完全退出 FireVibe 再重开**才生效。
> 界面上读不到遥控器时会直接提示，并给一个跳转按钮。

用内置语音转文字时还会弹一次**语音识别**授权，同意即可。

到这一步，方向键、音量、播放暂停已经能用了。其余按键在界面上点「添加按键」逐个配。

## 常见问题

**遥控器时连时断？**
换 1.5V 碱性电池。1.2V 充电电池满足不了蓝牙射频的峰值电流。

**授权了按键还是没反应？**
勾完「输入监控」要**完全退出再重开**才生效。升级新版本不用重新授权，配置也不会丢。

**电量数字一直不变？**
那个数字是遥控器自己通过蓝牙报的，应用只是原样显示 —— 在 macOS 的蓝牙设置里
看到的是同一个值。**部分仿品的固件把它写死了**（实测有一台不管电池实际剩多少
都报 96%，同一节电池换到原厂遥控上显示五六十）。这是设备固件的问题，改不了。
原厂遥控器报的值是准的。

**语音输入工具收不到麦克风键？**
用「第三方语音输入」动作，它是在硬件层做映射的 —— 有些工具只认硬件来源的按键。

**怎么卸载虚拟声卡？**

```bash
sudo rm -rf /Library/Audio/Plug-Ins/HAL/FireVibeMic.driver && sudo killall -9 coreaudiod
```

**硬件层映射残留了怎么清？**
正常退出会自动清，只有进程被强制结束才可能残留。手动清：

```bash
hidutil property --matching '{"ProductID":0x0421,"VendorID":0x0171}' --set '{"UserKeyMapping":[]}'
```

重启 Mac 同样会清掉。

## 给开发者

**Rust + [GPUI](https://www.gpui.rs)**（Zed 的 GUI 框架），界面和逻辑都是原生的，
没有 Electron / WebView。音频、HID、事件注入直接调 CoreAudio / IOKit / CoreGraphics。

```
core/     协议、配置、动作执行、语音识别、红外
cli/      命令行 firectl：按键测绘、原始报文嗅探、各类自检
ui/       桌面界面
driver/   虚拟声卡的构建脚本
```

工程细节、协议逆向记录、构建和签名的注意事项都在
[**开发笔记**](docs/DEVELOPMENT.md) 里。
